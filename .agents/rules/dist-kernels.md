## Distribution Kernels

- The cjk kernel packages follow `::gentoo`'s `gentoo-kernel` and `gentoo-sources` on the branches this overlay already carries. Whether a branch needs a bump is decided by `::gentoo`'s newest ebuild on that branch, read from the tree, not by kernel.org's release list.
- A cjk kernel bump copies these per-version variables from `::gentoo`'s same-version ebuild; it never derives them from the version number: `SHA256SUM_DATE`, `K_GENPATCHES_VER`, `PATCHSET`, `CONFIG_VER`, `GENTOO_CONFIG_P`.
- `PATCHSET` lags its branch: `gentoo-kernel-7.2.5` ships `linux-gentoo-patches-7.1.9`. A guessed `linux-gentoo-patches-7.2.x` does not exist.
- `CJKTTY_PV` names the cjktty patch, not the kernel version: it is the patch's `major.minor` (`7.2` for the 7.2.x branch, `6.18.45` for 6.18.x). A bump that crosses a branch boundary must move it, or the old branch's patch fails to apply.
- A point release inside a branch reuses the existing cjktty patch unless upstream changed a file the patch touches. Decide by fetching the incremental `.../incr/patch-A-B.xz`, not the full patch, and checking whether it changes any file under `drivers/video/fbdev/core/`, `drivers/tty/vt/`, `lib/fonts/`, or `include/linux/{console,font,vt_kern,consolemap}*`. If none, the patch and `CJKTTY_PV` are unchanged.
- `cjktty.eclass` points `SRC_URI` at raw addresses on `cjktty-patches` `master`, so those distfiles are live bytes: a change in that repository stales every Manifest that names them. Regenerate them together, after confirming the distdir copy equals `master`'s current bytes; `pkgdev manifest` rehashes whatever is in the distdir, and mirrors cache old copies.
- A cjk kernel `-bin` gpkg is built after the fact, so a source bump usually lands before its binary exists. Land the source, kernel, and virtual first, the virtual listing only the source provider; add `-bin` and its virtual entry in a second PR once the gpkg is published. A `-bin` trailing its source sibling by one point release is expected, not a retention that needs explaining.
- In a `virtual/dist-kernel-*-r100` `||` group, list `-bin` above the source package: the order is the preference order, so portage installs the prebuilt kernel instead of compiling one. List any other provider, such as `xanmod-kernel`, after the cjk providers.
- New genpatches lag on the personal mirrors `dev.gentoo.org/~alicef` and `~mpagano` while `distfiles.gentoo.org` already serves them, so a `DeadUrl` on such a URL is usually mirror lag. Re-check the primary mirror before acting.
